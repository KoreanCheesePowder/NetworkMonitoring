C.P Wallpad Network Monitor v1.1.4 업데이트 및 확인

1. 현재 네트워크 모니터링 장치의 설정값(1~8 대상 이름/IP/포트,
   검사 주기/시간 제한/연속 실패/성공 횟수)을 캡처하거나 기록합니다.
2. 기존 v1.1.3 ZIP과 이 v1.1.4 ZIP을 모두 보관합니다.
3. 수정 ZIP을 별도 새 폴더에 압축 해제하고 UPDATE-DRIVER.cmd 실행
   (SmartThings CLI 로그인 및 Edge 드라이버 패키징 권한 필요).
4. SmartThings 앱의 기존 '월패드 네트워크 상태' 장치를 삭제하지 마세요.
   추가 스캔으로 두 번째 장치를 만들지 마세요.
5. 장치 상세 정보 -> 제작자 정보의 드라이버 버전이 v1.1.4인지 확인하세요.
6. 1~8 대상 이름/IP/포트 설정과 루틴을 변경 없이 유지합니다.
   기존 상태 캐시가 없는 최초 업데이트 직후에는 초기 상태 이벤트가
   한 번 발생할 수 있습니다. 동일 장애 반복 알림 여부를 따로 확인하세요.
7. 설치 직후 재시작과 최초 정상 확인은 회복 알림으로 판단하지 않습니다.
8. 30분~1시간 동안 장치 통신 기능(현관문, ESL, 월패드 등)과
   SmartThings 네트워크 알림 상태를 관찰합니다.
9. 지속 장애가 확인된 경우 해당 대상의 설정 IP:TCP포트와 Edge 실시간
   로그의 'Confirmed TCP service failure' 문구를 함께 확인합니다.
   ('한 번의 TCP 실패'라는 경고만으로 장치 네트워크 장애는 확정되지 않습니다.)
10. 문제가 새로 생기면 기존 v1.1.3 소스에서 UPDATE-DRIVER.cmd를 실행해
    되돌립니다. 재페어링/장치 삭제는 필요하지 않습니다.

주의
- 초기 설치가 아니라 업데이트라면 SETUP-AND-INSTALL.cmd 사용 금지:
  신규 Device Presentation을 생성할 수 있습니다.
- 현 상태의 포트가 실제 전용 Health 서비스인지 이 ZIP만으로 확인할 수
  없습니다. 다른 기능에 사용 중인 TCP 포트를 반복 접속하면 영향을 줄
  가능성이 있으므로 ESP 펌웨어와 실제 대상 설정을 함께 검증해야 합니다.
- TCP 연결 검사만으로 ICMP Ping 장애, Wi-Fi 품질, Zigbee 링크 품질을
  판단할 수 없습니다.
- 검사 주기 10초는 현재 설정을 유지합니다. 통신 간섭이 의심되는
  서비스 포트라면 장비별 안전성을 먼저 확인하세요.
- 실제 SmartThings Hub 네트워크와 ESP 펌웨어에서 장시간 안정 동작을
  검증하기 전까지 '완전히 해결'됐다고 결론 내리지 않습니다.
